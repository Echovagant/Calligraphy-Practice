# 编码污染检测与机械修复脚本

`mojibake.py` 用于检测并机械修复后端源码里的 **UTF-8 被当成 GBK 解码** 造成的乱码污染。

## 背景

2025 年的一次批量转码事故把 `src/main/java` 下的 Java 源文件搞坏了：

1. 文件原本是 UTF-8；
2. 被按 GBK 解码（这一步有损）；
3. 再按 UTF-8 编码写回。

GBK 的解码器每次吃两个字节。当第二个字节（trail byte）小于 `0x40` 时，这一对是非法的，
解码器就把它换成一个 `?`。

所以每个 `?` 代表**丢失的两个原始字节**：

- 一个 GBK lead byte（`0x81`–`0xFE`）；
- 紧跟其后的那个 ASCII trail byte（`0x00`–`0x3F`）。

因为 trail byte 是 ASCII，损坏分成四类：

| 规则 | 现象 | 处理方式 |
| --- | --- | --- |
| A | 整段中文变成 `鍏堝皾璇曚粠鏅...`，但没有丢字节 | 可逆：`run.encode('gbk').decode('utf-8')` 直接还原 |
| B | `?` 吃掉了一个 `"` | 字符串字面量少了收尾引号 → **补 `"`** |
| C | `?` 吃掉了一个换行 | `//` 注释把下一行的语句吞掉了 → **补换行** |
| D | `?` 吃掉了别的 ASCII | 字节无法确定 → **交给人工** |

另外，`?` 还吃掉了它前面那个汉字的**最后一个字节**，所以那个汉字始终是残缺的。
规则 A 救不回来（这一段少了一个字节），这些行会写进报告交给人工。

## 怎么区分损坏标记和正常代码

事故产生的 `?` **一定跟在一个非 ASCII 字符后面**：解码器刚吐出一个双字节字符，
紧接着遇到了非法的 lead byte。

而跟在 ASCII 字符后面的 `?` 是**正常的 Java 代码**——三元运算符 `? :`、正则量词 `(?=`
——必须原样保留。

> 这一条把仓库里 56 处合法代码全部排除在外，也保住了 4 个已确认的合法三元站点。

## 怎么判断规则 B 适用

trail byte 只有一个字节，所以一行要么丢了一个引号，要么没丢，**引号个数会告诉你答案**：
受损的行比原来少一个引号。

具体到某个位于字符串字面量内部的 `?`：**它后面**的引号个数是偶数、**它前面**的引号个数是奇数
——这个 `?` 就是吞掉收尾引号的那一个。

如果一个候选集合里只有一种选法能让整行的字符串字面量全部闭合，就采用它；
有多种选法（歧义）就整行不动，写进报告交给人工。

## 怎么判断规则 C 适用

规则 C 只会插在**注释里**：`?` 处在 `//` 注释中间，而且它后面的文本是代码，
说明它吃掉的是那个注释结尾的换行符。

「后面的文本是代码」有两种判据，任意一种成立即可：

1. 后面紧跟着一段代码关键字（`return`、`public`、`Map<`、`@` …）；
2. 后面**先缩进再跟代码**。

第 2 条是关键。`?` 吃掉的是「上一个汉字的最后一个字节」加上**一个 ASCII 字节**。
吃掉换行时，后面跟的是**下一行源码的缩进**；吃掉别的 ASCII 字符时，
后面接的是同一行的句子，**不会缩进**。仓库里实测：

| `?` 后面 | 数量 | 判读 |
| --- | ---: | --- |
| 缩进 ≥ 2 空格 | 176 | 吃掉的是换行 → 补换行 |
| 0 空格 | 34 | 吃掉的是别的 ASCII 字符 → 不动，交给人工 |

> 这条把 `// 检查用户名是否存在?        if (repo.existsByUsername(name)) {`
> 这种被 `//` 吞掉的语句救回来——没它的话，接口方法声明会整条留在注释里，文件直接编不过。

## 用法

```bash
cd SpringBoot-Platform

# 自检：必须退出码 0
python scripts/mojibake.py selftest --root .

# 只检测，不修改。干净时退出码 0，发现污染时退出码 1
python scripts/mojibake.py detect --root .

# 试运行：打印影响面，并把无法自动判定的行写进报告
python scripts/mojibake.py repair --root . --report ../docs/mojibake-unresolved.md

# 真正落盘
python scripts/mojibake.py repair --root . --apply --report ../docs/mojibake-unresolved.md
```

### 参数

| 参数 | 说明 |
| --- | --- |
| `--root DIR` | 扫描根目录，默认为当前目录。脚本只处理 `<root>/src/main/java` 与 `<root>/src/main/resources` 下的 `.java` / `.sql` / `.properties` |
| `--apply` | 缺省是**试运行**，只统计不写文件；加上才写回源文件 |
| `--report FILE` | 把无法自动判定的行写进该 Markdown 文件（UTF-8） |

## 报告格式

```
UNRESOLVED <相对路径>:<行号> [marker|truncated-cjk]
    <该行内容>  [was line <修复前的行号>]
```

- 路径相对 `--root`，**用正斜杠**（跨平台一致）。
- 行号对应 **`repair --apply` 改写之后**的树；方括号里是修复前的行号。
  规则 C 会往行里插换行，所以两个行号会不一样。
- 报告里列出的是**仍然需要人工判断**的行，每行带一个原因标签：
  - `[marker]`——行里**还留着 `?`** 损坏标记；
  - `[truncated-cjk]`——行里的汉字串**少了一个字节**，它前面那个字仍然是残缺的
    （这种行里可能一个 `?` 都不剩，但字符照样是坏的，所以同样要列出来）。

> 报告末尾会给出两类各自的条数：`unresolved lines` 是总数，
> 下面跟着 `marker` 与 `truncated-cjk` 的分项计数。

## 注意事项

- **控制台输出刻意保持纯 ASCII。** 本机 PowerShell 控制台是 GBK，Python 用 GBK 写
  stdout 时遇到 `€`（U+20AC）之类的字符会抛 `UnicodeEncodeError` 并**中断整个脚本**。
  所以中文明细只写进 UTF-8 的报告文件，stdout 只打印 ASCII 摘要。
- **源文件统一改写为 LF 换行。** 仓库启用了 `core.autocrlf=true`，
  Git 会在提交时归一化，所以这一步不会污染 diff。
- **写入是原子的。** `--apply` 先把所有文件写到 `.mojibake.tmp` 临时文件，
  全部写成功后才逐个 `os.replace` 就位；中途失败会清掉临时文件，不会留下改了一半的树。
- **不是 UTF-8 的文件会被跳过**（`UnicodeDecodeError`），并在报告里列出，不会中断整轮修复。
- 脚本**只做机械修复**。报告中列出的行仍然需要人工判断后再改。
- 跑 `repair --apply` 之前建议先跑一次不带 `--apply` 的试运行，确认 `files changed`
  的规模符合预期。

## 自检覆盖了什么

`selftest` 里有十六个用例，任何一个失败都会以非 0 退出码退出：

1. **中文假阳性**——`岗位` / `状态` / `用户` 这样的正常词不能被规则 A 误判为乱码；
2. **规则 A 可逆**——一段固定的乱码样本必须能还原回正常中文；
3. **规则 A 的 C1 区拒绝**——往返结果落到 `U+0080`–`U+00FF` 的一律拒绝
   （`路` 会还原成 `U+00B7`）；
4. **规则 C 换行**——`// xxx?   String foo = ...` 后面跟代码时，要能把语句拆回独立的一行；
5. **规则 B 引号**——字符串字面量丢了收尾引号时，要把引号补回去；
6. **规则 B 反例**——字面量**已经闭合**时，绝不能再补引号（否则会变成三个引号）；
7. **合法三元/正则**——`jwt != null ? "***" : null` 与 `(?=.*[a-z])` 必须原样不动；
8. **字符串内的 `?`**——`@Mapping(expression = "java(x != null ? y : z)")` 不得被插换行；
9. **损坏标记识别**——跟在 ASCII 后面的 `?` 不是损坏标记；
10. **残缺汉字**——少了一个字节的汉字串必须被识别出来；
11. **仓库无关**——自检不依赖仓库当前状态，修完再跑也必须通过；
12. **残缺行留档**——仍然损坏的行必须出现在报告里；
13. **无 `?` 的残缺行也要留档**——只少了字节、没留下 `?` 的行同样要进报告，
    并标成 `truncated-cjk`；
14. **正确中文不进报告**——一行正常中文绝不能被当成残缺行列进报告；
15. **规则 C 的缩进判据**——`// 注释?        if (...) {` 这种被注释吞掉的语句
    必须拆回独立的一行；
16. **同行损坏不拆行**——`// 评分范围?1-10` 这种吃掉普通字符的必须留在原行。

> 自检用的是**内嵌的固定样本**，不读仓库，所以在一棵「已经修好」的树上跑也照样退出码 0。
